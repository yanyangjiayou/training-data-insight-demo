## 简介

某公司是一家外企连锁品牌，在中国拥有 1000+ 家线下门店，十分重视一线店员的培训（销售能力、标准话术），并建立了清晰、严格、与晋升直接挂钩的培训地图。

培训体系分为 8 个成长等级：`入1 → 入2 → E → B → A → Exp → SME → SMB`（SMB 为店长，SME 为副店长）。店员先完成线上培训，达到对应等级后参加考试；考试通过后报名线下研学；完成等级考试是晋升的必要条件。

不同层级的管理者（大区长 / 地区长 / 店长）需要随时掌握各大区、地区、门店的学习进度分布，识别问题突出的区域，从而进行针对性管理、合理调配线下研学资源。

本项目围绕两类需求展开：

1. **自定义报表**——按管理者关心的维度（大区 / 地区 / 门店 / 等级）及时、个性化地输出数据。
2. **自动化洞察**——在数据之上，按查看粒度与权限自动生成层级化洞察，把最核心的问题与建议直接呈现，便于管理动作落地。

## 功能特性

- **自定义数据宽表**：明细级宽表，覆盖每人每级的学习进度、线下研修与考试状态，支持按组织维度下钻。
- **业务对齐的自动洞察**：洞察不是对图表的复述，而是基于结构化的业务知识生成「现象 → 原因 → 建议动作」的结论，直接对应管理动作。
- **知识库驱动的洞察体系**：指标体系、预警规则、通知路由分层维护（详见 `system-config.json`），业务方在知识库中调整规则即可更新洞察，无需改动代码。
- **数据到落地的闭环**：每个指标映射到具体跟进动作；预警精确派单到责任人；超时未改善则按路由自动升级，把"发现一个问题"推进到"问题被跟进与销项"。
- **Excel 导出**：明细表支持一键下载 Excel，便于二次分析与离线汇报。
- **单文件、零依赖**：`index.html` 双击即可演示，便于分发与评审。

## 洞察体系：知识库驱动的三层结构

洞察逻辑不写死在报表里，而是一套由知识库维护、可自动迭代的体系。整体分为三层：

```
业务目标
  │
  ▼
① 稳定基线（指标体系 / 业务流程 / 指标↔标准动作映射）   ← 几乎不变，分析·技术团队维护
  │
  ▼
② 预警规则（触发条件 / 扫描频率 / 红黄阈值）           ← 业务方可在知识库直接改，最高频
  │
  ▼
③ 通知路由（预警通知给谁 / 责任人 / 时限 / 升级路径）  ← 业务方可配置，中频
  │
  ▼
行动闭环：派单 → 跟进 → 若超时未改善 → 按路由自动升级
```

| 层级 | 内容 | 维护方 | 变更频率 | 视觉标记 |
| --- | --- | --- | --- | --- |
| **① 稳定基线** | 指标体系、八级解锁业务流程、指标→标准动作映射 | 分析·技术团队 | 极低 | 蓝色 |
| **② 预警规则** | 触发条件 / 扫描频率 / 输出（判断阈值） | 业务方（知识库直接修改） | 最高频 | 橙色虚线框 |
| **③ 通知路由** | 预警通知给谁、责任人与时限（RACI）、升级路径 | 业务方（架构/分工调整时） | 中 | 紫色框 |

设计上，业务方在知识库中修改 ② 预警规则（如红/黄阈值、新增预警类型）或 ③ 通知路由后，无需改代码，AI 据此重新生成洞察与派单名单。体系依据页用颜色区分三类模块（② 预警规则＝橙色虚线框，③ 通知路由＝紫色框），便于一眼识别「稳定基线 / 可改规则 / 可配路由」。

> **背景参考**：在数据分析与 AI 应用领域，让 AI 产出"可行动的洞察"通常依赖受治理的指标定义与业务上下文（业界常称为"语义层 / 指标层 / 知识层"的收敛），而非仅对图表做自由发挥；告警侧则普遍采用"精确派单 + 超时自动升级"的路由机制，以避免告警疲劳与无人认领。本项目是把这套思路落到"培训学习地图"这一具体业务场景中的一个示例。

## 使用说明

`index.html` 集成三个标签页，可点击切换：

- **数据宽表**：查看明细数据，支持按组织维度下钻；右上角可下载 Excel。
- **数据洞察**：顶部为各等级当前阶段的人数分布摘要，下方为核心风险洞察（按风险重要性筛选）。
- **体系依据**：查看支撑洞察的完整逻辑——指标体系、预警规则与通知路由，按维护频率分层呈现。

## 配置：system-config.json

洞察体系以 `system-config.json` 表达为单一可信源（Single Source of Truth），便于版本化与维护：

- `baseline`：稳定基线，几乎不变。
- `alert_rules`：预警规则，业务方可频繁调整。
- `routing`：通知路由，业务方可配置。

修改 JSON 后，由知识库 / 生成流程重新生成洞察，无需改动页面代码。

> 进阶方向：可让 `index.html` 直接读取该 JSON，实现"配置即界面"。

## 技术实现

- **单文件三合一**：`index.html` 通过 `iframe + srcdoc` 内嵌三个独立文档，切换标签互不干扰，便于分发与演示。
- **洞察体系结构化**：`system-config.json` 显式分离三层，是知识库驱动洞察的落地表达，可版本化、可审计。
- **可视化**：洞察结论卡、KPI 摘要、层级框+箭头进度图、逻辑链路图均为原生 HTML/CSS/SVG，无第三方依赖。
- **数据下载**：明细表导出 Excel（演示中为脱敏合成数据）。

## 扩展方向

1. **配置即界面**：让 `index.html` 直接读取 `system-config.json`，业务方改 JSON 即改洞察。
2. **数据接入**：将示例数据替换为真实导出，并补充解析 / 分析脚本使报告可复算。
3. **权限与粒度**：按大区 / 地区 / 门店做数据权限隔离，管理者仅看自己辖区的洞察。
4. **定时洞察推送**：结合预警规则与通知路由，定时生成洞察并推送至对应责任人（企业微信 / 邮件），跑通"派单 → 跟进 → 升级"闭环。
5. **趋势分析**：从单期快照扩展为多期，补充同比 / 环比与趋势预警。
